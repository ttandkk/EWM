## 速度与背景 OOD 更新（2026-11-08）

本节优先于下文历史 OOD 配置。ID、光照、模糊的场景清单和训练采样不变。

- 速度基准为 **ID 区间边界**。若 ID 为 `[L,H]`，低速在下界外扩 10%–20%，
  即 `slow ∈ [0.8L,0.9L]`；高速在上界外扩 10%–20%，即 `fast ∈ [1.1H,1.2H]`。
  两个区间均严格位于 ID 外，不对每条 ID 速度乘倍率。
- 速度 OOD 合并为一个 `speed_ood` 条件：每任务共 **50 回合，slow 25 + fast 25**。
  前 25 个 ID 场景 slot 分配 slow，后 25 个分配 fast；各组在自己的绝对参数区间内
  独立分层均匀采样。保留全部 50 个 ID 初始场景，各模型复用同一清单，不按成功率重采。
  同时报告整体成功率（分母 50）和两组成功率（各分母 25）；未完成回合单独计数。
- 前七项分别改变带速、箱子峰值速度、角速度、滚动速度、向下初速度和抛物线水平速度。
  抛物线竖直初速、重力和发球点不变，接球位置会随水平速度变化。
- 容器的采样参数为飞行时间，慢对应更长时间，快对应更短时间。ID 为 `[Tmin,Tmax]` 时，
  `slow ∈ [Tmax/0.9,Tmax/0.8]`，`fast ∈ [Tmin/1.2,Tmin/1.1]`，在时间区间内均匀采样，
  再由原有弹道函数重算初速；保留 ID 空间网格、发球点和时刻。合并条件按回合独立采样；
  显式单独运行历史 `slow`/`fast` 时，成对轨迹仍共享飞行时间。
  配置允许范围为 `[0.65/1.2,0.70/0.8]` 秒，ID 采样范围仍为 `[0.67,0.68]` 秒。
- 当前 `tennis_falling` ID 下限为 0.25 m/s，支持 slow。显式历史 v1 的下限为零，
  无法按此规则构造严格更慢的下落速度；请求该历史 slow 条件会报错，不生成重叠样本。
- 清单记录 `speed_reference_boundary`、相对边界的 `speed_multiplier`、实际值及
  `piper_id_boundary_speed_ood_v3` 版本，并校验 OOD 参数区间与 ID 不相交。
  合并分布版本为 `piper_speed_ood_balanced_v1`，每回合的 `speed_condition` 标记 slow/fast。

## 八动态任务模型闭环测评实现（2026-10-21）

入口：`scripts/eval_piper_eight_dynamic.sh`；调用现有 EWM 策略服务和任务闭环客户端，
实际执行模型动作。使用独立 `evaluation` 随机流和固定场景清单；同任务各条件配对，
所有场景只尝试一次，失败计入分母，不调用专家或向模型提供物体真值。
每条件 50 回合：8 项各 6 条件，总计 **48 组、2400 回合／模型**（旧版为 47 组、2350 回合）。

## 3. 历史动态速度分布（传送带范围已由上方 2026-10-21 更新覆盖）

### 3.1 定义

对于三个新增动态任务，设中心速度参数为 `s0`，ID 下、上界为 `L`、`H`：

```text
L = 0.7 × s0
H = 1.3 × s0

ID       : U[L, H]
慢速 OOD : U[0.85 × L, L)
快速 OOD : U(H, 1.15 × H]
```

**15% 相对于对应 ID 边界计算。** OOD 不包含 ID 边界值。每回合采样一次速度参数，回合内保持不变；往返运动的瞬时速度仍按既定运动方程变化。

以下仅描述历史协议，不用于新版传送带采集或评测。原传送带是历史例外：已有训练数据实际使用 `U[0.04, 0.08] m/s`，相对中心 `0.06 m/s` 为 ±33.3%。保留这个 ID 范围，并从它的真实边界向外扩展 15%，避免把训练见过的速度标记成 OOD。

圆盘角速度一行的数值为展示用舍入值，实际采样按公式计算，使用精确中心 `s0 = 0.06 / 0.095 rad/s`。

### 3.3 运动方式保持一致

- **原传送带**：保持原来的运动方向和场景布局，改变带面线速度。
- **移动纸箱**：往返幅度固定为 `A = 0.06 m`。采样峰值速度 `v_peak`，令 `ω = v_peak / A`；沿当前输送方向作 `y(t) = y_center + A × sin(φ + ωt)` 运动。速度参数表示峰值，瞬时速度自然经过零；改变峰值速度时相应改变周期。
- **圆盘套杯**：中心角速度来自原来的标称线速度 `0.06 m/s` 和轨道半径 `0.095 m`。按角速度划分 ID/OOD；杯子位置扰动会改变实际半径和线速度，因此不用单个杯子的瞬时线速度重新分类。圆盘尺寸、中心和转向固定。
- **旋转试管架**：保持架体、孔位、孔径及旋转方向，只改变角速度大小；初相位按第 2 节采样。

## 4. 新数据采集规则

1. 新增任务的训练和验证示范只使用 ID 速度与标准成像，不加入本文定义的光照、模糊或速度 OOD。
2. 动态速度采用均匀分层采样，覆盖整个 ID 区间；每个分层内均匀抽样，打乱执行次序。预先生成并记录速度清单。
3. 采集保留成功示范，同时记录全部失败尝试。失败补采时保留对应速度，不换到更容易的速度；若某个速度段反复失败，应先修复专家，不能删除该速度段。
4. 成功示范必须经过完整物理任务判定。物体安置后的操作依赖物理接触，不使用抓取附着或中途写位姿完成任务。
5. 新任务扩大随机化后，先进行专家验收再批量采集。已有几条成功预览不能替代随机化验收。
6. Push-T pose-v2 的 50 条按位置 X、Y 和 yaw 分别分成 50 个等宽区间，独立打乱组合后各取一条；yaw 的五个 18° 大区间各含 10 条。失败补采保持三个分层编号，仅在原区间内重新抽样，不能跳过困难角度。原 Push-T 小扰动数据不修改、不混入新版数据。

采集元信息应记录任务版本、代码快照、种子、实际初始位姿、速度参数及单位、运动初相位、相机和渲染配置、成功判定版本、尝试结果及失败原因。旧数据继续使用已有元信息，不回写修改。

### 5.1 光照 OOD

以各任务采集时的标准光照强度 `L0` 为基准：

- 变暗 25 回合：强度倍率均匀采样于 `[0.4, 0.6]`。
- 变亮 25 回合：强度倍率均匀采样于 `[1.4, 1.6]`。

倍率在回合开始前确定，回合内固定。RGB 和事件由扰动后的同一场景生成。其他成像设置固定，避免自动补偿抵消预设光照变化；实际倍率与成像设置记录在测评清单中。

实现补充（2026-10-21，适用于当前八个动态任务）：

- `piper_tasks/lighting.py` 提供 `piper_fixed_scene_lighting_v1`：独立随机流均匀采样暗光／亮光各 25 回合并打乱顺序；不改变初态、ID 速度或发球时间。

| 曝光时长 | 回合数 |
| ---: | ---: |
| 16.67 ms | 10 |
| 20.83 ms | 10 |
| 25.00 ms | 10 |

不得使用 `t_k` 之后的图像。事件建帧仍使用 `(t_(k-1),t_k]`，不随 RGB 曝光改变。

## 6. 方法间公平比较与延迟

- **固定场景清单**：各方法复用同一份初始位姿、运动相位、速度和扰动清单，按 trial 配对比较；保存实际参数，不能仅依赖种子推断配置一致。
- **保留失败**：失败回合保留在分母中，不以成功场景替换，不按模型结果筛选正式测评场景。
- **统一成功规则**：同一任务的全部方法及条件使用同一成功判定和时限，不因 OOD 调整判定标准。
- **正式测评开启实测等效延迟**：支持编译的模型完成编译与预热后再测；统一硬件、控制频率和动作调度，记录编译实际启用状态、动作就绪延迟及任务完成时间。模型预热不得改变正式回合的初始场景。
- **零延迟为独立消融**：明确标注结果所属时钟与调度方式，不与等效延迟结果混合汇总。
- **TTT 与记忆**：TTT 参数在验证集确定，每回合重置适应状态；记忆每回合清空。测评真值只用于成功判定与事后分析，不作为策略或 TTT 的额外输入。
- **测试集隔离**：不根据正式 OOD 测评结果调参或选择 checkpoint；训练、验证和测试用途保持分离。

### 8.1 一次提交新增六项

在项目根目录执行：

```bash

bash scripts/collect_piper_six.sh --dry-run

bash scripts/collect_piper_six.sh --parallel-tasks 6
```

任务顺序为 `push_t`、`drawer_cup`、`square_nut`、`moving_carton`、`turntable_cups`、`rotating_tube`。当前账号常规队列限制为两张 GPU、最多五个提交任务，因此默认提交一个双节点作业，每节点一张 Pro6000，每张卡串行处理三项任务，同时采集两项。`--parallel-tasks 6` 提交一个六节点作业，使用账号已有的 `override-limits-but-killable` 可抢占 QOS，六项同时采集。两种模式都只在每张 GPU 上启动一个 Isaac 进程；此前三进程共享一张 GPU 的小测初始化耗时很长，不再作为默认方式。资源到位时间由 Slurm 决定；仿真固定为 120 Hz 物理、30 Hz 控制、240 Hz EVIS 插值。

正式训练数据直接写入 `datasets/piper_<任务名>/`；运行日志、源码快照和中间审计默认位于 `tmp/piper_collection_runs/train_<UTC时间>/`。运行前复制源码快照并保存 SHA256；各数据集保存相机、预采样速度清单、初始位姿、成功和失败尝试、物理终态及归一化统计。双 RGB 为 H.264，双事件帧为 Parquet 内嵌无损 PNG；保留原 Piper 的 8 维状态、7 维动作和观测前动作对齐契约。只有成功采满且终态、数据及视频检查通过，才写入 `.export_complete`。

`--split-jobs` 沿用两卡模式的分组：组 0 为 `push_t / square_nut / turntable_cups`，组 1 为 `drawer_cup / moving_carton / rotating_tube`。两个作业各申请一个节点、一张卡，独立调度，无相互依赖；共享只读源码快照，写入各自任务的目录。提交编号及组别记录在 `submitted_jobs.txt` 和 `submitted_groups.tsv`。该选项仅支持 `--parallel-tasks 2`，可搭配 `--smoke`；续采时也需保留 `--split-jobs`。

可以用 `--tasks` 选择已通过小测的部分任务，保留原分组和顺序，并将选择写入 `launch.json`；续采时须提供相同任务列表。子集模式只支持两卡调度，每组至少选择一项：

```bash

PIPER_GPU_GRES=gpu:l40:1 bash scripts/collect_piper_six.sh --split-jobs \
  --tasks square_nut,moving_carton,turntable_cups,rotating_tube
```

小测仍在排队或运行时，可预提交正式采集，用 `--after-jobs JOB0,JOB1` 指定组 0、组 1 各自的小测作业：

```bash
PIPER_GPU_GRES=gpu:l40:1 bash scripts/collect_piper_six.sh \
  --split-jobs --after-jobs 207906,207907
```

每组正式作业只依赖对应小测的 `afterok`：三个场景的专家验收、1 条试采及 RGB/event/数据校验全部成功，且小测正常退出后，正式作业才可调度。小测失败、取消或超时会自动取消该组等待中的正式作业，另一组不受影响，小测日志保留；修复后须重新小测并挂接新的作业。该过程由 Slurm 执行，无需保持终端或对话连接。正式采集写入独立目录，每任务目标 50 条，仍先进行协议规定的 10 次专家验收、要求至少 9 次成功。组号、正式 job、小测 job 的映射追加记录在 `submitted_dependencies.tsv`。挂接时应核对正式源码与小测使用的场景、专家及采集源码一致。

```bash

bash scripts/collect_piper_six.sh --smoke

# 续采必须保持原来的任务数、种子、相机、渲染及源码快照。

```

`--resume` 会检查导出条数与尝试记录的一致性；中断若落在无法确认的写入阶段，会保留文件并报错，不能当作已成功导出继续计数。单任务专家验收失败或尝试预算耗尽时返回失败，其他任务继续完成并保留各自结果。`PIPER_GPU_GRES=gpu:6000ada:1` 可将每节点 GPU 改为 RTX 6000 Ada；默认仍为 Pro6000。

专家更新为 `push_t_pose_v2_contact_reach_v9`，仅修改控制轨迹：

- 纠偏统一使用横梁左端，按误差符号切换接触面，使初始外侧位姿的纠偏推力朝内；行程随角度变化，限制为 8–40 mm。
- 横向接触回到细杆中心线，去除原先朝横梁的偏置；接近退距从 30 mm 缩至 20 mm，同步缩短空走行程。真实闭合指尖网格的接触高度半宽约为 X 12.18 mm、Y 7.45 mm，保留几何间隙。
- 远端下降及推挤使用不超过 0.10 rad 的固定小倾角，避免关节 5 在直立腕姿下饱和；空中换位恢复径向腕姿。
- 主平移允许最长 30 cm，覆盖大角度纠偏后的剩余距离，减少无必要的分段换位。

第一次候选 v8 在物理回放中仍出现超时和 IK 发散，诊断作业 `209832` 已停止，未生成正式数据。v9 诊断作业 `209845` 重放旧失败边界与控制案例；结果写入 `tmp/push_t_fix_20261018/v9_probe/results/results.json`。实际物理质心为局部 `(0, 0.0146739, 0)` m；把名义侧推接触移到该质心并未改善实际偏转，因此本次接触改动依据有限指尖与桌面摩擦的物理回放，不能解释为“修正错误质心”。

当前通过 46 项相关 CPU 回归（采集与控制 24、Push-T 分层与提交 8、静态任务 14）；95 个初态首次接近/下降/推挤/抬手的离线 URDF 检查最大位置残差约 4.67e-8 m，下降终点无指尖网格顶点进入 T 块。离线检查不是完整碰撞检测或物理验收。仍须完整 35/35 固定边界、至少 9/10 独立随机验收以及 1 条 RGB/event 导出校验通过，才自动启动 50 条正式采集；正式输出为 `datasets/piper_push_t/`。本次不改变协议、初态清单、45 秒上限和成功条件，也不触碰已有七个数据集。
